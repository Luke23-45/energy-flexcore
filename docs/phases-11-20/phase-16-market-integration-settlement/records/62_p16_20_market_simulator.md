## 2. Recorded decisions

1. **RECORDS ONLY, never a connection** (`PAPER_LOOP_STATEMENT`, `SIM_FEED_IS_SIMULATION_STATEMENT`, `SIM_EXPORT_SINK_STATEMENT`, all pinned by tests): there is no socket, no HTTP, no FIX/ICCP/SCADA stack, no broker anywhere in the tree. The simulated feed is in-process; the simulated sink holds a `Vec`; the statements are strings and node trees. This is the plan §8 criterion 2 deliverable shape.
2. **No money arithmetic in floats** (plan §4; hard ban 9): every price, amount, quantity, and imbalance value is generated in INTEGER arithmetic (tenths/cents) and rendered as wire-faithful decimal text; the exact-decimal parse stays at the P16.07/P16.09 record boundaries (`fixed_decimal`). No float→money conversion path exists; no RNG exists (the determinism rule — same inputs ⇒ byte-identical records, the replay/benchmark feed).
3. **The engines are consumed, never redefined**: the loop's bid output IS `compose_bid`'s; the reconciliation output IS the P16.09 engine's; the statements parse through the P16.09 grammars; the price records assemble through the P16.07 record layer. The loop adds exactly three simulator-local RECORD types (dispatch instruction, evidence record, ledger reference) and none of them touches a command, a payment, or a counterparty.
4. **The dispatch leg stays paper** (`PAPER_DISPATCH_STATEMENT`, pinned): the P14.16 command-relay-only rule is consumed by citation — a real instruction enters only through the 14-state command lifecycle with validation, feasibility, and authorization as distinct gates; the simulator never issues, never authorizes, never constructs a forward lifecycle state.
5. **The composition→application dependency edge is legal with NO checker change** (recorded manifest note): `flexcore-simulator` is a COMPOSITION crate in `tools/check_dependency_rule.py`; composition crates are not edge-restricted, only CORE crates are checked, and nothing may depend ON a composition crate except apps. `flexcore-application` is an existing workspace member — NO new external dependency (hard ban 7 holds), and the checker was not edited (outside file ownership).
6. **Sim identity, forever** (the P14.17 identity rule carried to the market tier): `sim://market` / `sim://statement` / `sim://market/paper` / `sim-export://` prefixes on every identity string — a record produced FROM the simulator is identifiable from its identity alone, forever. No fixture value carries market meaning.

## 3. Honest boundaries

1. Nothing has ever run: no cycle has been executed, no publication generated, no statement parsed, no receipt recorded. Every test is WRITTEN-UNRUN; execution is the human gate.
2. The simulator has never fed replay or a benchmark: no replay record, no benchmark figure, and no observed value exists anywhere (X-8: any future benchmark thresholds are registered BEFORE the first run that could fill them; observed values stay structurally separate).
3. The payment-state leg is a REFERENCE by design: the P16.14 payment-lifecycle module (wave-2 Agent A, concurrent) is the vocabulary's single home. This loop enters NO state, mirrors NO vocabulary, and records NO payment; the wait-check at batch close recorded whether A's module had landed (it had NOT at P16.20 write time — see record 63 §3 and the close-out reconciliation).
4. The export receipts are bookkeeping for the paper loop, never telemetry evidence about any market; the sink implements the seam in-process and must never be presented as a transport.
