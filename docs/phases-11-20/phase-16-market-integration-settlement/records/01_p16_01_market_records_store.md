## 2. Recorded decisions

1. **Audit-chain linkage: the P11 chain is CONSUMED, never redefined.** Every record row carries `audit_record_id uuid NOT NULL` — the P11 `audit_records` row (migration 0008; the P11.15 chain columns 0019) that the CALLER appends through the P11 sink in the SAME unit of work. No chain columns exist on any market-records table; the keyed-HMAC chain treatment, the NULL-while-unkeyed semantics, and the LR-203 production-crypto requirement stay exactly where P11.15 put them. The write-path obligation is stated on the trait header, the adapter header, and here. No FK to `audit_records` (the linkage is the recorded reference; a cross-migration FK would couple migration units).
2. **Append-only supersede model.** All six record tables are INSERT + SELECT only. A lifecycle transition, a contract change, or a corrected statement is a NEW row whose `supersedes_*` link names the row it replaces (the D-P4.10-3 supersede discipline mirrored for financial records); readers derive currency from the links, never from an UPDATE.
3. **Money discipline (plan §4; hard ban 9).** `amount_text` is explicit decimal text bound AS TEXT; `currency_code` is a three-letter code carried as DATA (ISO 4217 as recorded data, re-verified at use — the contracts crate has no currency unit, and none is invented here). No float money arithmetic is representable; no total, revenue figure, invoice, or payment is computed anywhere in this batch.
4. **Retention rows carry no universal period** (P0.16 §4; the P1.10 `RetentionPolicy` Unset-default rule mirrored at rest): the UNSET shape carries NO period and NO basis; the CONFIGURED shape requires BOTH — enforced by the row constructor and a table CHECK.
5. **Expand-only** (MIGRATION_POLICY §1/§2): every statement is a CREATE TABLE / CREATE INDEX on NEW, EMPTY tables (always safe) plus grants and RLS policies. No ALTER touches an existing table. The down migration is destructive by definition and exists only to complete the pair; on evidence-class tables it would require operator sign-off (policy §3).
6. **ADR-011 boundary restated.** `jurisdiction`, `event_kind`, and `line_item_kind` are DECLARED/RECORDED data with bounds, deliberately NOT universal taxonomies; the `source_format` vocabulary is closed at design level to the four formats the plan names, with additions as additive migration decisions — never silent.
7. **LR-074/190 closes at DESIGN level only.** The P9.22 §5 statement ("the market-records store DOES NOT EXIST — settlement evidence storage has no implemented store today; a recorded GAP, not a hidden one") is now superseded by: the schema and contract EXIST as written-unrun artifacts; nothing has been migrated, nothing has been written, and the store is empty everywhere.

## 3. Honest boundaries

1. No market is connected, no registration is filed, no qualification is claimed, and no settlement number, revenue figure, invoice, or payment exists anywhere in this batch (plan §8 criteria 3–4).
