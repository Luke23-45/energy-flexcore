# W1.01 — F-16 scope statement and non-goals

Workstream: FlexCore control-plane work

- **Objective:** Write the F-16 scope statement and non-goals from design §3.1, including the full not-initially list, so every later F-16 subtask can test scope creep against it.
- **Design trace:** Design §3.1
- **Inputs / prerequisites:** Design §3.1; W0.05 baseline record; W0.08 Gate 0 handover.
- **Steps:**
  1. Transcribe the §3.1 product statement (tenant-scoped assessment and resource-onboarding workflow for commercial and industrial facilities) in substance.
  2. Reproduce the full not-initially list: not an auditor replacement; not automatic ASHRAE certification/sign-off; not a full ISO 50001 EnMS; not a BMS/EMS/SCADA replacement; not a new DR baseline engine; not a new VPP optimizer; not a substitute for commissioning/interconnection/OT-security/device-safety.
  3. State the defining output: a structured, evidence-backed representation of a facility's energy resources, operational constraints, efficiency opportunities and available flexibility (per foundations.md F-16 definition).
  4. Circulate the scope statement to product and power-systems reviewers.
- **Deliverable / output:** An F-16 scope statement and non-goals note, versioned, with the not-initially list intact.
- **Acceptance criteria / exit check:**
  - [ ] The note states the §3.1 product statement and the defining output (asset and flexibility inventory for FlexCore).
  - [ ] All seven not-initially items appear, none dropped or softened.
  - [ ] The note states F-16 is a tenant-scoped workflow for commercial and industrial facilities.
  - [ ] Reviewer acknowledgement is recorded or the objection is recorded.
- **Owner role:** Product
- **Dependencies:** W0.05, W0.08
- **Verification method:** Line-by-line comparison against design §3.1 and foundations.md §7 item 1.
- **Risks / failure modes:** A non-goal (for example automatic ASHRAE sign-off) re-entering via a demo or report claim. Mitigation: the scope note is the scope-creep test at every F-16 gate.
